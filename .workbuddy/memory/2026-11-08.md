## 15:40 desk audit: the 512 B wall is almost certainly the MFG AXI 1-to-2 glue

- MGM: DT node is empty (only "compatible"), group table lives in LK/GPUEB. 2409
  already excluded the tag itself.
- GMPU: real, but it is the protected-memory-allocator's table (4 MiB table, 16
  MiB reserve, programmed via GPUEB GPR), so it only guards protected buffers and
  cannot explain stalls on ordinary DRAM pages.
- Candidate found: gpufreq_mt6983.c:3323 __gpufreq_acp_control(), run on EVERY GPU
  power-on. It sets MFG_AXCOHERENCE 0x13FBF168 |= 0xF and, more importantly,
  mfg_axi1to2_R_dispatch_mode = 0x855 (in) / 0x055 (out) into
  0x13FBF8E0/8E8/910/918 and 0x13FBF900/908/920/928. A 1-to-2 AXI bridge splits by
  an address bit and has no other dimension -> matches "one half of every 1 KiB".
- Measured proof the block is unprogrammed: 0x13FBF748 reads 0x06000006 while
  __gpufreq_slc_control() writes 0x06002006 (bit 13, "R cache").
- panthor only writes 0x13000000..; 0x13fbf000 is MTK glue the DDK assumes the
  platform did. Our shim powers the GPU on itself and skips it.
- 2413 design: 2412 byte for byte + that glue before MCU_CONTROL, dispatch words
  before/after to console, diag_flags bit for "glue applied". input_va 4 = wall
  gone; input_va 3 + same output_va = glue is not it.
